# LegacyLock 审计修复说明

日期：2026-09-20。基于原审计的 20 项发现，修改当前工作区源码及文档。没有提交 Git、发布安装包、修改真实密库、格式化设备或写入真实 U 盘。

## 主要变化

原问题涉及密钥来源和写入授权，无法只靠按钮禁用修补。本次建立统一 LVCF 3 协议，将密钥操作、所有者签名、角色授权、磁盘保存和设备路径选择集中到 Electron 主进程。

- 本机和备份使用随机数据密钥；密码加安全密钥通过固定参数 scrypt 解开所有者槽。
- 两盘各持有独立随机恢复秘密。两份一起只能解开数据密钥，不获得签名私钥。所有者凭据才可签署资产、设置和恢复配置更新。
- 只读导入保存原签名加密快照；所有重启均锁定。主进程拒绝只读会话修改、删除、设置、重配两盘和导出管理备份。
- 保存队列、临时文件、fsync、rename、上一份加密快照及读回验证替代浏览器存储与明文降级。写入状态不确定时锁定，不继续使用旧内存覆盖磁盘。
- 真正制作、读取、验证双份密钥及两盘密库副本；同一物理盘的两个分区不能被视为两盘。更换两盘时同时轮换数据密钥；没有格式化动作。
- 不再发布原 Rust 写入器或调用 PATH 密码工具。旧 Rust CLI 仅用于历史数据抢救，修复异常 nonce 崩溃，去掉日期导致的抢救阻断。
- Electron 升级至 44.4.3；开启 sandbox/contextIsolation，限制 IPC 发送者和主 frame，阻断外部请求、导航、弹窗和权限请求，取消端口复用。
- 新界面明确标出所有者/只读身份、本机保存/两盘备份状态、取消/失败结果，以及重新生成密钥后的备份确认。保留 24 类资产、自定义字段及附件。

## 兼容性及功能调整

1. 新密库格式升级为 LVCF 3，旧密钥不能直接用于新密库。旧版加密导出包与有完整认证信息的旧本机存储有明确迁移入口；建立新身份后须重配两盘。不会自动覆盖旧数据。
2. 日常所有者解锁改为密码与安全密钥同时验证，停用单 PIN、单密钥和缺失配置自动授权。密码最少 12 位，新密钥为 256 位随机值。
3. 当前产品界面集中于中文密库核心流程。原有订阅演示、主题/语言切换、托盘常驻、双重缩放、伪迁移进度及一键销毁未接入新入口；它们不能被当作当前已验收功能。保留其历史源码不表示继续支持旧权限实现。
4. 所有者导出沿用当前本机密码和密钥，更换凭据后应重新导出与同步。旧备份不会自动改密。每次资产保存只保存本机，需要主动同步两盘。
5. Rust v1 历史模型可用独立 CLI 抢救为明文，当前桌面不自动将此模型转换为新资产。保留原件、核对后录入；不能据此声称所有旧格式均一键迁移。
6. 只读保护针对应用能力与原所有者签名，不能阻止获得明文者另存/编辑副本，也不能抵御已控制操作系统的攻击者。
